Dates

Before 1.0.0

Priority order. Item 2 is the one in progress.

1 · Security

Close the enforcement gaps, in the platform and in what it generates

Two dependency trees. A weakness we ship is ours; a weakness we generate is deployed by someone who trusted the generator.

  • Topology guard fails open. sys_workflow_transitions is missing from the scaffold array in nestjs-backend.generator.ts, so its migration never renders, the seed fails, and entity-access.guard.ts reads zero rows — its if (validEdges.length > 0) check then permits every state transition. CI stays green over it.
  • Every guard needs a negative test. A permitted action passing proves nothing; only a forbidden action being refused catches a fail-open.
  • Demo credentials must not survive deployment. Generated apps seed admin@admin.com / admin.
  • Secrets. SESSION_SECRET, JWT_SECRET, DB_ENCRYPTION_KEY; what a generated .env.example implies is safe; what reaches logs and process listings.
  • Route coverage. requireProjectAccess on every project-touching route; injection through model-supplied identifiers; rate limiting.
  • Dependency scanning in CI, both trees.
Done when

Every advertised access rule has a test asserting refusal; a generated app cannot deploy with a demo credential live; dependency scanning gates CI on both trees; open findings are published, not summarised as “enterprise security”.

2 · In progress

Full pipeline on the DeepSeek harness, and usability

  • Whole pipeline, not a model swap. Domain → entity → relationship → ERD agents, the retrieval feeding them, HITL review and generation, all exercised on the harness and kept green in CI.
  • Usability. Infer what can be inferred instead of asking; errors that state the fix, not the failure; output the checker accepts without hand-editing.
Done when

A plain-English description produces a model the checker passes 0 errors / 0 warnings and an application that runs, on DeepSeek, with no hand-editing — identically from the hosted page and the CLI.

3 · Documentation

Document the product, not just the language

The guide builds a CRM. The spec is EML, for language models. Neither documents the generator.

  • Install; the project wizard and what each step expects; the rule and workflow editors; enhance and deploy.
  • What generation emits, and how to keep working on a generated app.
  • The parts that surprise people: two stacks from one model, no per-entity source in the browser stack, generated apps carrying their own manual, tests and migrations.
Done when

Someone new goes clone → deployed → modified on the documentation alone, without opening source to learn what a screen does.

4 · Testing

End-to-end coverage over the whole surface

CI already generates an app, builds both halves, migrates, boots and runs a generated suite — twice, once on WebAssembly Postgres. That is a foundation, not coverage.

  • The modelling tool's own screens, end to end.
  • Regeneration over an application someone has already edited.
  • Suites that tolerate failure. migrate.ts logs a failed seed and continues, so a broken seed exits 0. A green build must be evidence.
Done when

Every user-facing path has a test that fails when it breaks, and no suite logs past a failing step.

5 · Licensing

Audit both dependency trees against Apache 2.0

A generated application is the user's to own, sell and relicense. A copyleft dependency arriving via a template takes that away silently.

  • Actual license per component, read from the package — not assumed.
  • Build-time or shipped at runtime: the obligations differ.
  • Compatibility with Apache 2.0 in that role; any copyleft flagged.
  • Whether it reaches a generated app, and on what terms the user then holds it.
Done when

A checked-in inventory across both trees, a NOTICE discharging attribution, a written finding per incompatibility, and a CI check that fails on an uncleared license.

After 1.0.0

Item 7 is a large part of why item 1 is security.

6 · Research agent

Close the loop, on a local model

Today Try It Yourself sends you out: copy a prompt, take it to ChatGPT or Gemini, bring back a .mmd. The highest-value step runs on a service we don't control, with your business description in it.

  • Plan, search, read, follow, weigh sources, revise, cite — aimed at one deliverable: a model the checker accepts.
  • All inference on the configured local default, mlx-community/Qwen3.8-27B-4bit. Making 27B sufficient for planning, tool use and long-context revision is the work — not a frontier API with a local fallback.
Done when

“Build me an application for X” produces a researched, cited model and a running application — no external API call, on hardware a small company owns, HITL review still ahead of code generation.

7 · Autonomy

OpenClaw inside a sandbox that does not trust it

  • Runtime: OpenClaw — heartbeat, installable skills, persistent memory, driving the loop a person drives today, against the local model from item 6.
  • Containment: NVIDIA OpenShell — kernel-level isolation, declarative policy over filesystem, network and binaries, enforcement outside the agent, full allow/deny audit trail. Runs OpenClaw unmodified.
  • Why containment first: an agent that installs packages, learns skills at runtime, spawns subagents and pushes to a repository can do each of those wrong. Self-propagating attacks across agent ecosystems are published literature.

Two open questions, stated rather than glossed. “Automate everything” is in tension with the human-in-the-loop review this project calls its differentiator; the working boundary is autonomy over the mechanical loop (regenerate, build, test, document, deploy, keep CI honest) with a person still ahead of the model itself — and this page will say so if that boundary moves. And OpenShell is early preview: depending on it is a bet.

Done when

The agent takes a model from approved to deployed and keeps it there with no human in the mechanical path; every action is readable afterwards from the sandbox audit trail; the policy denies by default; and removing the agent leaves a repository a person can still work in.

How this list is kept

Versioned with the site — its history is the change log. Nothing is marked done until its Done when is true. Order and contents change; a Done when does not get quietly softened.

Open an issue if the order is wrong. Items 1 and 5 are the ones an outside reader is best placed to hole.
