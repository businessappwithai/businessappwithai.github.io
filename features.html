Business Rules and Validation Engine

Encode your organization's business logic using visual decision flowcharts. The GoRules Zen Engine executes DMN-based rules with high performance at runtime.

🔒

Field-Level Validation

Required fields, range validation, format patterns, uniqueness enforcement, conditional requirements, cross-field validation, and Zod-schema rules — all generated automatically per entity.

📊

Document-Level Rules

Three-way matching, budget threshold checking, duplicate detection, completeness checks, and complex cross-document validations driven by GoRules decision tables.

🔗

Relationship Integrity

Referential integrity rules prevent orphaned records, control deletion permissions, and maintain data consistency across related entities — enforced at both the API and database levels.

⚡

Lifecycle Hook System

Define business rules in natural language using visual flowcharts. AppWithAI generates executable TypeScript code organized by entity lifecycle events.

Lifecycle Hook Events

beforeCreate

Field auto-population, validation, duplicate detection before record creation

afterCreate

Trigger notifications, create related records, initiate workflows

beforeUpdate

Validate field changes, check authorization for status transitions

afterUpdate

Audit logging, cascade updates to dependent records, notify stakeholders

beforeDelete

Block deletion if dependent records exist or document is approved

customValidate

Complex cross-document, cross-entity validation logic

Workflow and Document Routing Engine

State machine-based workflow engine routes documents through your organization for review, approval, escalation, and action — with full audit trails.

Conditional Routing

Approval paths adapt dynamically based on document content:

  • • Route to Level 1 approver if amount is below $1,000
  • • Route to Level 2 approver for amounts $1,001–$10,000
  • • Route to Finance Director for amounts above $10,000
  • • Route to Legal if contract type is External Party

Escalation and Timeouts

Automatic escalation rules ensure documents never stall:

  • • Auto-escalate if no action within configurable SLA window
  • • Reminder notifications at configurable intervals
  • • Multi-level escalation chains for senior approvers
  • • SLA breach detection and alerting

Parallel Routing

Simultaneous approvals from multiple departments:

Approval Stamping and Audit

Enterprise-Grade Security

Generated applications include a comprehensive, layered security model — from authentication through to individual field visibility per user role.

Security Architecture — Four Layers

Authentication Layer

Session management via Better-Auth — supports OAuth providers, email/password, and MFA-ready flows

Role Assignment Layer

Users are assigned to one or more roles. Roles aggregate granular permissions for table, field, and row access

Table-Level Access Control

Roles are granted Read, Create, Update, and Delete permissions at the table level via sys_access_role

Field-Level Access Control

Individual columns can be marked visible, editable, or hidden per role — enforced at the API level via sys_access_field

Row-Level Security

Users see only records belonging to their department, region, or organizational unit — enforced via sys_access_record policies

Document Status Security

Approved or completed documents are locked from editing, preserving the integrity of the audit trail

AI Copilot Interface

Every generated application includes an embedded AI assistant powered by CopilotKit. End users get a conversational interface for natural language data queries, in-context guidance, and intelligent suggestions — directly within their application.

What Users Can Do

  • "How many invoices are pending approval right now?"
  • "Show me all purchase orders from Vendor X this quarter"
  • "List all employees who joined in the last 30 days"
  • "Which products are below their reorder level?"
  • "What contracts expire in the next 90 days?"

Security Is Never Compromised

The AI Copilot query interface honors the same security model as the rest of the application:

  • ✓ Users can only query data they are authorized to access
  • ✓ System administration tables are inaccessible
  • ✓ Field-level permissions are enforced per query
  • ✓ Row-level security filters are applied automatically
  • ✓ Query complexity limits prevent resource exhaustion
  • ✓ SQL injection patterns are detected and blocked
